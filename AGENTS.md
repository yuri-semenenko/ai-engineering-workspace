# AGENTS.md

Repository contract for `ai-engineering-workspace`, and tool-agnostic: Codex and
Gemini CLI read it directly, Copilot CLI and VS Code read it as agent
instructions, and root `CLAUDE.md` imports it for Claude Code. It is a router —
what is specific to this repository, plus a link to the document explaining each
rule. It does not restate the README, the persona, the methodology, or the skill
catalog.

## Purpose

A portable methodology layer for *using* AI to do software engineering, shipped
to four assistants: Claude Code, Codex, GitHub Copilot, and Gemini CLI.

## Instruction layers

Six layers reach an assistant from here. Put a change in the layer that owns it.

| Layer | Owner | Loading model |
| --- | --- | --- |
| Persona | `persona/*.template.md` | generated by the wizard, installed per tool |
| Methodology | `docs/principles/` | prose, read on demand |
| Repository contract | that repository's root `AGENTS.md` | always-on repository context |
| Skills | each tool's skills/commands/prompts directory | task-triggered |
| Adapters | `claude-code/`, `codex/`, `copilot/`, `gemini/` | tool-native delivery by the installers |
| Guardrails | `settings.example.json`, `scripts/`, `scripts/hooks/`, CI | mechanically enforced |

Persona and methodology are global and shared. A repository contract is neither:
never copy persona, methodology, or a whole skill into one.

### Six files share two filenames

Tool discovery dictates both names, so none of these can be renamed. Always say
which one you mean by its path.

| Path | Scope |
| --- | --- |
| `AGENTS.md` (root) | this repository's contract — the file you are reading |
| `codex/AGENTS.md` | personal and global; installed to `$CODEX_HOME/AGENTS.md` |
| `copilot/workspace-template/AGENTS.md` | a template for *another* repository; not in force here |
| `CLAUDE.md` (root) | this repository's Claude Code adapter: the active `@AGENTS.md` import plus any Claude-only delta |
| `copilot/workspace-template/CLAUDE.md` | the `@AGENTS.md` adapter shipped with that template; not in force here |
| `persona/CLAUDE.md` | the developer's generated persona, gitignored, installed to `~/.claude/CLAUDE.md` |

`persona/CLAUDE.template.md` is canon for the condensed persona, not one of these
six. Do not merge any of these and do not add a sync between them; only the
persona and memory-seed mirrors are generated pairs. Rationale and the rejected
alternatives: [`docs/architecture.md`](docs/architecture.md) and
[`adr/0014-agents-md-is-the-repository-contract.md`](adr/0014-agents-md-is-the-repository-contract.md).

## Authoritative sources

Canon is edited by hand; mirrors are generated and committed so each tool folder
stays standalone-portable. Full reasoning in
[`docs/architecture.md`](docs/architecture.md).

- `persona/persona.template.md`, `persona/CLAUDE.template.md`,
  `claude-code/.claude/memory-seed.example/` — **canon**; edit here.
- `codex/references/persona.md`, `codex/references/memory-seed.example/`,
  `gemini/references/GEMINI.md` — **generated mirrors**; never hand-edit.
  Regenerate with `scripts/sync-codex-references.sh`.
- `codex/skills/`, `gemini/commands/`, `codex/references/checklists/`,
  `codex/references/humanizer/` — **owned here**: hand-authored ports with no
  canon to regenerate from. The sync script validates their structure only.
- `persona/persona.md`, `persona/CLAUDE.md`, `persona/recommended-skills.md`,
  `persona/copilot-instructions.md`, `claude-code/.claude/settings.json` —
  **wizard output**, gitignored and per-machine. Not the repository's to edit.

## Commands

Verified against `.github/workflows/ci.yml`.

| Task | Command |
| --- | --- |
| Regenerate mirrors | `scripts/sync-codex-references.sh` |
| Drift guard (what pre-commit runs) | `scripts/sync-codex-references.sh --check` |
| Repository contract guard | `scripts/check-repository-contract.sh` |
| Contract guard plus its fixtures | `scripts/test-check-repository-contract.sh` |
| Model-tier guard plus its fixtures | `scripts/test-check-model-tiers.sh` |
| Installer outcome reporting | `scripts/test-installer-persona-outcomes.sh` |
| Copilot workspace contract delivery | `scripts/test-copilot-workspace-contract.sh` |
| Shell syntax | `bash -n` over every path from `git ls-files '*.sh'` |
| Windows suite (ports and installers) | `pwsh scripts\test-windows.ps1` |
| Enable the pre-commit drift guard | `git config core.hooksPath scripts/hooks` |

There is no package manager, build step, or test runner: this repository ships
Markdown, shell, and PowerShell. `test-windows.ps1` is the PowerShell counterpart
of the Linux CI job, not an extra suite.

## Architecture invariants

- **One canon, committed mirrors, a guard that fails on drift.** After editing
  any canon file, run the sync script and commit the regenerated mirrors in the
  same change ([ADR-0001](adr/0001-single-canon-with-generated-mirrors.md),
  [ADR-0002](adr/0002-commit-mirrors-instead-of-generating-at-install.md)).
- **Every tool folder is standalone-portable.** `codex/`, `copilot/`, and
  `gemini/` must install from a copy of that folder alone, with no build step.
- **Every `.sh` has a `.ps1` port.** Change one, change the other, and run the
  Windows suite. Line endings are pinned by `.gitattributes`: `.sh` and
  `scripts/hooks/*` are LF, `.ps1` is CRLF. Never commit mixed endings.
- **A committed `model:` field names a tier alias** (`opus`, `sonnet`, `haiku`,
  or `inherit`), never a version slug
  ([ADR-0012](adr/0012-tier-labels-over-pinned-model-slugs.md)).
- **`adr/` is append-only.** Record a new decision as the next numbered ADR and
  supersede an old one rather than editing it. Before changing the canon/mirror
  split, the persona axes, the delegation policy, or the repository contract,
  read the ADR that decided it.
- **Root `AGENTS.md` owns every repository-wide rule; root `CLAUDE.md` is its
  adapter.** A rule that applies to any assistant goes here. `CLAUDE.md` may hold
  a genuinely Claude-only delta, but never a copy of a rule from this file, and
  its `@AGENTS.md` import must stay active — not backticked, fenced, or commented
  out. `scripts/check-repository-contract.sh` checks the pairing and the import;
  the no-duplication half is a boundary you keep, not something shell can prove.

## Change policy

- Keep changes scoped to the request; propose a larger refactor separately.
- Sterility is a hard rule: no real names beyond `LICENSE`, no employer or client
  names, no private paths, tokens, transcripts, or machine-local state. Anything
  person- or project-specific ships as a `*.template.md` with `{{PLACEHOLDERS}}`.
- Small, logically-grouped commits. No `Co-Authored-By` trailers and no
  AI-attribution footers in commits, PR bodies, or review comments.
- Process over codegen: a skill encodes how a senior engineer works, not "write
  my feature for me".

Full contribution rules in [`CONTRIBUTING.md`](CONTRIBUTING.md).

## Definition of done

1. `scripts/sync-codex-references.sh --check` exits 0.
2. `scripts/test-check-repository-contract.sh` exits 0 (it runs the guard against
   the checkout first, then its fixtures).
3. `test-check-model-tiers.sh` if you touched committed config;
   `test-installer-persona-outcomes.sh` and
   `test-copilot-workspace-contract.sh` if you touched an installer.
4. `pwsh scripts\test-windows.ps1` if you touched a `.ps1`, an installer, or
   anything an installer copies.
5. State explicitly what was not run and why.

## Safety boundaries

- **`scripts/create-persona.sh` and `scripts/check-recommended-skills.sh`
  overwrite `persona/persona.md`, `persona/CLAUDE.md`,
  `persona/recommended-skills.md`, and `persona/copilot-instructions.md`.** Those
  four are the developer's own gitignored profile. Run them against a
  fresh-clone-equivalent copy instead: `git ls-files` plus
  `git ls-files --others --exclude-standard` into a scratch directory, then run
  the copied script there. Both scripts resolve paths from their own location.
- Run installers only against a scratch `$HOME`, `$CODEX_HOME`, or workspace
  directory. Against a real home they replace `~/.claude`, `~/.codex`,
  `~/.copilot`, or `~/.gemini`.
- No commits, branches, pushes, or pull requests without explicit approval, and
  never to a default branch.
- Never commit auth files, tokens, credentials, transcripts, logs, caches, or
  lockfiles. `.gitignore` and the write-time secret scan are backstops, not
  permission to be careless.
